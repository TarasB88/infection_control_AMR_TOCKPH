# Архітектура зберігання даних IPC & AMR

## Єдине джерело даних

**Google Sheets — єдина база даних системи.** Одна приватна Google-книга містить робочі аркуші, довідники та користувачів. Cloudflare D1, SQL та інші бази даних не використовуються.

Google Forms призначені для внесення даних закладами. Google Forms записують відповіді в окремі вкладки тієї самої книги. Apps Script bridge об'єднує ці відповіді з відповідними наборами даних під час читання дашбордом.

Cloudflare Worker роздає frontend і надає API. Він не зберігає робочі дані. Стан користувацьких сеансів є stateless підписаним токеном із терміном дії 8 годин; таблиця Google Sheets залишається єдиним постійним сховищем даних.

## Аркуші робочої книги

- `Facilities` — реєстр закладів.
- `Facility_IPC_Profile` — організаційний IPC-профіль.
- `IPC_Visits` — моніторингові візити.
- `IPC_Assessments` — результати оцінювання IPC.
- `Recommendations` — коригувальні заходи.
- `Training_Events` — навчальні заходи.
- `Training_Facility_Stats` — охоплення навчання за закладами.
- `AST_Data` — результати фенотипового AMR/AST.
- `WGS_Staging` — дані геномного нагляду.
- `Legal_Acts` — нормативно-правові акти.
- `Dictionaries` — довідники.
- `Users` — облікові записи дашборду.

Вкладки, яких бракує, створюються через Apps Script bridge. Наявні заголовки не перезаписуються.

## Внесення даних через Google Forms

Відповіді форм слід спрямовувати до тієї самої робочої книги. Вкладки відповідей перейменовуються відповідно до конфігурації в `integrations/google-apps-script/Code.gs`:

| Модуль | Назва вкладки відповідей |
|---|---|
| IPC visits | `Form_IPC_Visits` |
| IPC assessments | `Form_IPC_Assessments` |
| Training | `Form_Training_Events` |
| AST | `Form_AST_Data` |
| WGS | `Form_WGS_Staging` |

Заголовки запитань мають збігатися з назвами колонок цільового аркуша (наприклад, `Facility_ID`, `Visit_Date`, `SIR_Category`). Колонка Timestamp, яку додає Google Forms, ігнорується при зіставленні. Дані форм читаються разом із рядками основного аркуша; вихідні відповіді форми не переписуються.

## Доступ та авторизація

Користувач входить у дашборд через логін і пароль. Власний Google OAuth у браузері відсутній.

Аркуш `Users` має структуру:

`Username | Password_Salt | Password_Hash | Email | Full_Name | Role | Is_Active | Facility_Codes | Created_At | Updated_At`

Паролі не зберігаються у відкритому вигляді. Worker створює індивідуальну сіль і PBKDF2-HMAC-SHA256 хеш (210 000 ітерацій). Токен сеансу підписується HMAC-SHA256 та діє 8 годин.

Ролі:
- `admin` — доступ до всіх функцій і керування обліковими записами;
- `operator` — читання та внесення робочих записів;
- `analyst` — читання без запису.

Поле `Facility_Codes` зберігається в профілі, але обмеження даних на рівні окремих закладів ще не реалізоване. Не слід трактувати його як фактичне row-level security.

## Безпека Apps Script bridge

Apps Script Web App виконується від імені власника книги. Зовнішній доступ до Web App потрібен, щоб Cloudflare Worker міг викликати його без інтерактивного входу користувача. Кожен запит має містити секрет `SHEETS_BRIDGE_SECRET`, який зберігається лише в Apps Script properties та Cloudflare Worker secrets. Він ніколи не передається браузеру.

Параметри Cloudflare Worker:
- `SHEETS_SCRIPT_URL` — URL розгорнутого Apps Script Web App;
- `SHEETS_BRIDGE_SECRET` — секрет, згенерований `setupBridge()`;
- `SESSION_SIGNING_SECRET` — випадковий секрет щонайменше 32 символи для підпису сеансів;
- `BOOTSTRAP_KEY` — окремий одноразовий ключ для створення першого адміністратора.

Якщо секрет bridge буде скомпрометований, згенеруйте новий у Apps Script properties і оновіть відповідний Worker secret.

## Межі застосування

- Книга має залишатися приватною; не публікуйте її в Інтернеті.
- Доступ до Apps Script deployment захищений секретом bridge, але власник книги та редактори Apps Script мають повний доступ до даних.
- У поточній версії ролі розмежовують операції читання/запису та адміністрування, але не обмежують доступ за окремими закладами.
- Не використовуйте систему для зберігання прямих ідентифікаторів пацієнтів без окремої оцінки правових підстав і безпеки.
